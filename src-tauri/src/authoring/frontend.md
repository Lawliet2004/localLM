Design around the audience and primary task before styling. For an existing product, extend its design language. For a new product, choose a specific visual direction tied to its purpose: typography, spacing rhythm, palette, imagery and interaction density. Express these as reusable tokens. Avoid generic interchangeable card grids and invented marketing copy. A dashboard needs clear operational hierarchy; a reading surface needs comfortable typography; a marketing page needs a coherent story and credible content.

Implement the main journey end to end. Every visible button, link, search, filter, menu and form must work or be explicitly unavailable with an explanation. Use semantic HTML, visible focus, accessible names, keyboard navigation, proper form labels and associated errors. Cover loading, empty, success, failure and disabled states. Preserve entered data when validation fails. Never present simulated server success as a real integration.

Compose distinct primary and secondary information, aligned baselines, consistent spacing, restrained borders and intentional whitespace. Use existing icon primitives, meaningful visuals, readable contrast and a focused type scale. Keep typography crisp with sensible line lengths; avoid shrinking content to force it into a fixed screenshot. Design narrow/mobile layouts as deliberate compositions. Prevent overflow from long content and test zoom, touch targets and reduced motion.

Verify representative routes and states: narrow and wide viewports, keyboard-only interaction, a completed primary action, validation failure and empty results. Inspect console/network failures and layout only through available, authorized tools. Fix evidence-backed problems and then polish hierarchy, alignment, copy and motion. Report source/build checks separately from visual inspection; if visual tools are unavailable or declined, say that visual quality remains unverified.

Before substantial styling, record a compact visual direction and use available relevant design skills progressively. Inventory real assets and use authorized asset acquisition or generation where needed. After implementation inspect the primary journey at wide and narrow sizes when permitted. Record concrete defects in hierarchy, layout, content, behavior or accessibility; repair these specifically, then capture the changed states again. If visual observation or image input is unavailable, retain that limitation in the acceptance checklist and final report.
