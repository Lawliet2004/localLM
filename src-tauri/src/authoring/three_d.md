Clarify the deliverable from the request: an interactive 3D scene, an editable model, a game asset, or a rendered image. Deliver actual geometry and the requested native/export files; a screenshot or CSS illustration is not a 3D model. Inspect existing tooling and installed versions before choosing Three.js, Blender, Godot or another engine. Do not assume Blender or an export plugin is installed.

Plan the object's silhouette, proportions, dimensions/units, assembly and material palette. Construct meaningful geometry with appropriate normals, topology and transforms. Use instancing/reusable geometry for repetition. Avoid excessive subdivisions, accidental intersections, detached parts and inconsistent scales. For assets, consider origin/pivot, naming, UV/material needs and polygon budget. Preserve editability when requested.

Frame the complete object deliberately using bounds, aspect ratio, a usable camera target and sensible near/far planes. Use lighting and material roughness/color that reveal form. Tune shadows, environment and background together. Orbit/zoom controls need sensible limits and a useful reset view. Implement resize, device-pixel-ratio limits, loading/error states and a fallback if WebGL is unavailable. Clean up GPU resources, controls and listeners on unmount.

Use existing/local assets or permitted acquisition tools; do not fabricate textures, download URLs or generated images. If an external asset is essential and unavailable, state the limitation or create an intentional procedural substitute. Export using the actual supported API and check that the saved file exists and can be parsed: geometry, bounds, materials and external-resource references. An export button that never creates a valid file does not satisfy model delivery.

Verify build and geometry invariants separately from rendering. If permitted tools can render, inspect multiple useful viewpoints, clipping, proportions, lighting and interaction; inspect exported assets with a real importer when available. Never claim a render/export was inspected from source alone. Explain any unchecked visual or native-tool requirements.

Review a blockout from front, side and perspective before detailed modeling. Correct silhouette and proportions first. Organic/sculptural requests may need specialist modeling or asset-generation capabilities; do not quietly substitute a collection of primitives. Inspect exported files with an actual importer when available. Record which views and export checks were observed; do not describe source-only inspection as rendered acceptance.
