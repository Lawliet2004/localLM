Start from the existing service architecture, API contracts, data model, runtime and deployment constraints. Build the complete requested request-to-storage-to-response path. Agree on observable acceptance criteria through a short plan for substantial tasks. Avoid inventing provider credentials, running services or database contents.

Define and validate input/output contracts at boundaries. Handle malformed input, missing records, conflicts, authorization failures and server errors with stable status codes and useful messages. Keep internal details and secrets out of responses/logs. Implement real authentication/authorization only through the actual configured mechanism; never use a decorative login screen or trust client-supplied ownership. Bound request sizes, pagination and expensive operations.

Use real persistence when requested. Make schema changes explicit and reversible where practical, preserve existing data, and use transactions for related writes. Consider unique constraints, concurrent requests, retry/idempotency semantics and resource cleanup. Do not silently replace persistence with in-memory arrays. Label mocks/local fixtures as such and keep them separate from production configuration.

Read actual versions and official documentation before using unfamiliar APIs. Use environment configuration without exposing secrets. Return clear startup/configuration errors rather than fabricated successful responses. Keep routing, business rules and storage responsibilities understandable; avoid unnecessary infrastructure for a small task.

Verify happy paths and meaningful rejected/error paths with actual tests. Exercise persistence across requests/restarts where required, authorization boundaries and a relevant concurrency case. Run migration/build/type checks appropriate to the stack. An import or successful process launch is not an integration test. Distinguish unit checks, real database/HTTP checks and unperformed deployment verification. Finish with concrete run/configuration instructions and honest limitations.
