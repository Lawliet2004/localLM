# LocalLM interface

This system replaces the previous neutral blue desktop presentation for the requested home and settings redesign. Product facts are recorded in PRODUCT.md.

## Visual language

Warm paper surfaces, forest text, and a restrained green accent make long working sessions feel calm. Light surfaces are #fcfcf8, sidebars #f3f3ed, and application chrome #eeeee7; green #356349 marks actions, current selections, and focus. Dark appearance uses green charcoal surfaces with pale sage accents. Shared values live in src/tokens.css.

IBM Plex Sans carries headings, application text, labels, navigation, and controls. Fonts are self hosted under src/assets/fonts with the accompanying license. Body text uses 14px, secondary controls 11–13px, section titles 15px, the home heading 26px, and settings page titles 31px. Do not add eyebrows, decorative gradients, or ornamental motion.

## Composition

The persistent 56px navigation rail sits beside contextual project or settings navigation. The main canvas and sidebar share one rounded outer frame. New conversation is the primary sidebar action. Empty projects explain the purpose of adding a folder.

Home places a modest heading and a single composer in one centered group. Remove marketing copy, empty workspace labels, and footer slogans. Show model setup guidance below the composer only when needed. Conversation starters live inside the collapsed Suggestions disclosure and close after selection. Project selection remains available in the workspace header; show the composer project strip and trajectory after a conversation begins. Existing conversations retain the scrolling message area and bottom composer. Starter buttons populate the draft and focus the input. Model, attachment, context, plan, and approval controls keep their original behavior.

When the active project is known, home shows it as a quiet pill under the heading. In conversations, user messages are compact bubbles and the copy action appears beside the bubble on hover or keyboard focus (always visible on touch devices). Project rows keep chevron, folder, name, and count on one line; the active chat is marked by the accent bar on the tree line, not the project row.

Settings use a centered readable column, consistent section dividers, aligned preference controls, and searchable navigation. Appearance includes selectable miniature previews synchronized with the native theme select. Permissions display the actual approval mode and scope. Workspace actions lead to their existing destinations. Secondary settings pages inherit the same colors, spacing, typography, and control treatment.

## Components and states

Use 8px control radii and 12–14px grouping radii. Borders describe surfaces; shadows are reserved for overlays. Green is an action or state signal. Keep native selects, visible labels, accessible icon names, and keyboard focus. No decorative loading sequence. Respect reduced motion.

Below 760px, project navigation becomes an overlay and settings navigation becomes a scrollable horizontal strip. Preference rows stack. The composer wraps its controls below 420px. Short windows scroll the home group instead of clipping its beginning.
