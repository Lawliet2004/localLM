# AREX research tools

Research mode offers `search`, `visit`, `update_context`, and `finish` alongside its existing web tools, using the argument names in [BAAI's published tool definitions](https://huggingface.co/BAAI/AREX-Turbo/blob/main/inference/prompts.py). Standard and other web-enabled modes switch search/fetch tools to these contracts when the selected model name/path contains `AREX`. Chat and Minimal modes do not gain web access. Existing conversations refresh their tool catalog automatically.

- `search({query: string[]})`: 1–4 queries, up to ten results per query before fusion. Uses the configured search provider and fallback without a nested model planning/synthesis call.
- `visit({url: string | string[], goal: string})`: 1–4 HTTP(S) URLs, using the existing protected fetch/extraction worker. One worker process fetches the batch in parallel and returns bounded text with per-page failures; the calling model evaluates the text against the goal. It does not automatically verify or summarize the page.
- `update_context({context: string})`: up to 16,000 bytes of model-authored notes with facts, URLs, uncertainties, rejected paths, and next steps. Archives older model/tool exchanges and keeps user instructions plus the current tool exchange intact. Transcript/audit rows remain available. Automatic compaction preserves the latest live checkpoint.
- `finish({answer: string, evidences: [{evidence: string, url: string}], confidence: string})`: returns the supplied answer and supporting source links directly and ends the turn. Confidence accepts a score from `0%` to `100%`; it is model-reported, not an independent verification score. Empty evidence is allowed for an honest unresolved answer. After a successful `finish`, a deterministic claim audit checks the answer's extracted claims against the text collected during the run plus the cited evidence; the result is appended as a `Claim audit` note and stored as a `verification` run/session event. The audit is lexical — it flags unsupported wording but does not prove truth, and it never blocks or rewrites the answer.

`finish` and `update_context` must each be the only call in their batch. Normal permissions, cancellation, result bounding, and auditing still apply. The research guard counts `search`, `visit`, and context updates; rewriting context does not count as new evidence. The guard warns after two unproductive calls, finalizes after four, and has a 24-call backstop (batches can contain up to four queries/URLs).

This is an adaptation, not a reproduction of BAAI's evaluation environment. It uses LocalLM's structured tool-call transport; the model runtime should support the model's tool-call template/parser. When a model emits literal `<tool_call>{...}</tool_call>` or `<function=name>{...}</function>` text instead of structured deltas, the chat loop parses complete leading blocks and executes them through the same permissioned dispatch (malformed or truncated blocks still fail the turn). BAAI's raw XML-only inference example is not a separate execution protocol here. The benchmark instruction that every question is guaranteed to have an answer is deliberately not used.

Foreground child agents support these control tools. Background children support the store-only control tools, but web search/visits still require the foreground dispatcher, like the existing web tools.

The fetch cascade can optionally render challenge-interstitial or JS-dependent pages with the local headless Edge installation (`msedge --headless --dump-dom`), since WebView2 already requires Edge on Windows. Enable it with `"fetch": { "jsRenderFallback": true, "jsRenderTimeoutMs": 20000 }` in `web-search.json`. It is off by default, runs the same SSRF/public-address check before spawning, never renders a page that robots.txt refused, and its output flows through the same extraction and challenge checks as a static fetch.

Two wire quirks are normalized because llama.cpp can pass AREX's XML parameters through as strings: structured parameters that arrive as JSON text inside a string (e.g. `url: "[\"https://…\"]"`) are decoded before validation, and `confidence` accepts a bare number or a percentage string.

Validation: `cargo test --manifest-path src-tauri/Cargo.toml --lib`, `npx vitest run src/web/arex.test.ts src/web/phase1.test.ts`, `node --test scripts/web-render.test.mjs`, and `npm run build`.

Live validation (2026-09-20): `bartowski/BAAI_AREX-Turbo-GGUF` `Q4_K_M` (sha256 `ccd279d1…b0e2b`) on the bundled llama-server, RTX 2050 4 GiB, 32K context. The model emitted structured `tool_calls` (the jinja template maps its XML format to OpenAI tool calls — the text parser is only a fallback). A research question ran `search` → `visit` → `finish` against a real SearXNG and live pages in six rounds, and the post-finish claim audit executed. Reproduce with `npm run test:arex-loop -- "question"` — it spawns llama-server on port 8081 and drives the bundled worker; a SearXNG at `127.0.0.1:8080` is required (Docker compose, or the WSL setup in WEB_SEARCH_PHASE1.md).
