## Execution approach

Use `devin --model swe-2-max` for successive implementation passes and review/fix passes. Each pass has a bounded file/task scope, meaningful regression tests, and a recorded result. Read current code before implementing; findings are hypotheses until confirmed. Do not remove existing approvals, uncertainty protections, source selection, path containment, artifact bounds or protocol compatibility to make checks pass. No wholesale reformatting or unrelated refactors. No new dependency unless a required capability cannot reasonably use an existing one. Use local fixture servers and fake processes for reproducible validation; never require user secrets or paid live services for automated tests.
