# LocalLM full application audit — 16 October 2026

**Remediation:** the original 24 findings have been fixed. See [the completed remediation plan and verification](AUDIT_REMEDIATION_PLAN.md), including an additional HTML extraction fix found during integration. The findings and baseline results below describe the original audit snapshot.

Audit target: the current working tree at commit `5eb2ba3d135725dc0a9bc6fb7156bf983e25d718`, including existing modified and untracked application files. Findings describe that snapshot, not only the committed version.

Reviewers: Codex and an independent **SWE-2 Max** review through the installed Devin CLI (`devin 3000.11.92`, explicit `--model swe-2-max`). Application source was not fixed, formatted, reverted, or committed during this audit. Build outputs and QA captures were regenerated by checks.

## Verdict

**Release should wait for the workspace-boundary and data-loss defects below.** Passing frontend tests do not cover these failure paths. The most consequential problems concern an auto-approved file-search tool, project identity, legacy HTTP fetching, unsent drafts, storage failure recovery, and background-agent history corruption.

Current consolidated findings: **24 — 11 P1 and 13 P2**, including one development-dependency advisory. A10 and A11 share the unconditional tool-assembly root cause and describe two separately testable user failures. Bundle-size and detector observations are listed separately and are not counted as bugs.

Evidence labels:

- **Executed — native:** exercised the current compiled Rust implementation against disposable files or an owned loopback server.
- **Executed — UI:** exercised real React components in Chrome with isolated native API fixtures. This establishes frontend behavior, not native IPC or OS behavior.
- **Source traced:** followed the current implementation through the relevant caller and callee. No live exploit or external service action is implied.
- **Advisory:** dependency finding from the installed lockfile and the current advisory database; application exploitability is assessed separately.

P1 means a major correctness, data integrity, availability, or security-boundary problem. P2 means a narrower defect or a problem with a usable workaround. No P0 incident or compromise was established.

## Findings

### A01 — P1: Auto-approved file search escapes the workspace and reads credential files

**Location:** `src-tauri/src/sandbox.rs:579–618`; `src-tauri/src/harness.rs:179–183,565–571`.

**Trigger:** Put a directory symlink or file symlink inside a selected workspace, pointing to a readable file outside it, then call the harness `file_search`. A non-hidden credential file such as `secret.pem` inside the workspace is also searchable.

**Actual:** The search follows links through `path.is_dir()` and `std::fs::read()`, returns matching outside content, and does not apply the credential-file policy. **Expected:** assistant file tools remain within the workspace and respect the same sensitive-file exclusions as workspace reads.

**Evidence — executed, native:** The disposable fixture returned all three: `linked-file.txt`, `linked-directory/private.txt`, and `secret.pem`, each containing a fake marker. The real helper was linked from the freshly compiled application library. `file_search` is classified as a trusted read, so Auto-approve reads supplies no extra approval barrier. No real secret was read.

**Fix:** Implement search through the capability-relative workspace reader, reject links at every level, and share sensitive-file validation with the existing workspace tool policy. Regression coverage should include file links, directory links, credential extensions, and links swapped during traversal.

### A02 — P1: Adding two folders with the same basename replaces a project

**Location:** `src/components/Sidebar.tsx:128–137`; `src-tauri/src/workspace_ui.rs:91–103`; `src-tauri/src/chat.rs:1407–1412`.

**Trigger:** Add `/one/api`, then `/two/api`.

**Actual:** Both requests use ID `api`. The backend removes the existing row with that ID and inserts the new path. Existing conversation metadata still refers to `api`, so old chats now resolve to the second folder. Name normalization also creates collisions between different names and many non-ASCII names. **Expected:** distinct folders have distinct stable IDs; adding a folder cannot silently change another project's path.

**Evidence — executed UI plus source trace:** The real Sidebar issued two save requests with the same ID; the fixture applying the backend's upsert semantics ended with one project, `api (/two/api)`. The backend's replacement and chat workspace resolution are explicit in the cited source.

**Fix:** Generate a UUID for new projects, or let the backend assign one and use the returned ID. Treat editing an existing project as a separate explicit action. Preserve conversation associations in a regression test.

### A03 — P1: Legacy web fetch checks DNS separately from the actual connection

**Location:** `src-tauri/src/sandbox.rs:401–424,507–514,529–550`; dispatch at `src-tauri/src/harness.rs:558–563`.

**Trigger:** An approved `web_fetch` targets an attacker-controlled hostname whose DNS answer changes between validation and connection.

**Actual:** `check_fetch_host` resolves and validates addresses, then reqwest resolves the hostname independently for `.send()`. Redirect checks repeat the same separation. **Expected:** the actual socket uses only the already validated public address, with hostname/TLS identity retained.

**Evidence — source traced:** No pinned resolver or reqwest address override connects the check to the request. This is distinct from `scripts/web-transport.mjs`, which pins validated DNS into the socket. No DNS-rebinding exploit was executed. Approval authorizes the named URL; it does not make a promised private-network restriction effective.

**Fix:** Route this alias through the pinned transport, or install a validated per-request resolver and disable unintended proxy bypasses. Test validation/connection address disagreement and every redirect hop.

### A04 — P1: Legacy fetch and search enforce size limits after reading everything

**Location:** `src-tauri/src/sandbox.rs:556–563,600–609`.

**Trigger:** `web_fetch` receives a very large response, or `file_search` encounters a large file such as a GGUF, database, or log.

**Actual:** HTTP uses `response.bytes()` before truncating to 256 KiB. File search uses `std::fs::read()` before checking its 512 KiB limit. Both allocate and read the entire input. **Expected:** stop consuming data at the enforced bound; oversized inputs cannot exhaust application memory.

**Evidence — executed, native:** An owned loopback fixture transferred **4,194,304 bytes** before returning a 262,144-byte excerpt. The private-fetch flag was enabled only to permit this owned loopback fixture; the body-read path is shared with ordinary public fetching. A disposable 64 MiB file was skipped only after reading it; the probe reached **68,484 KiB peak RSS**. Multi-GB exhaustion was not attempted.

**Fix:** Stream at most limit plus one byte, check metadata as an early optimization, and retain the streaming bound even when metadata is absent or changes. Bound aggregate search work as well as individual reads.

### A05 — P1: A full or denied local-storage area blanks the application

**Location:** `src/components/Sidebar.tsx:57–62`.

**Trigger:** Sidebar width storage throws `QuotaExceededError` or storage access is denied.

**Actual:** The unguarded storage read or effect write throws outside the draft/appearance recovery handling. React removes the application tree. **Expected:** retain a default/session width and keep the workspace usable.

**Evidence — executed, UI:** A browser fixture that makes `Storage.setItem` throw produced two `Quota exceeded` errors, an empty body, and zero children under `#root`.

**Fix:** Guard both access paths and use an in-memory fallback. A narrowly scoped error boundary can contain unexpected panel failures, but should not replace proper storage error handling. Repro artifact: `ui.json`, `storage-quota.png`.

### A06 — P1: Sending without a project destroys an unsent draft

**Location:** `src/App.tsx:567–574`; `src/components/Chat.tsx:654–672`.

**Trigger:** A local or API model is ready, no project exists, and the user sends a draft, with or without attachments.

**Actual:** Chat clears the draft and attachments before calling `onSend`. App reports “Add a project folder first, then send” and returns successfully. Chat therefore does not restore the unsent work. **Expected:** preserve the draft and attachments until the message is accepted, or reject the send so restoration runs.

**Evidence — executed, UI:** `Important audit draft` became an empty composer; zero conversations were created and zero messages were sent. Repro artifact: `flows.json`, `no-project.png`.

**Fix:** Validate prerequisites before clearing, return an explicit accepted/rejected result, or throw on this branch. Cover both text and attachments.

### A07 — P1: The folder chosen in Tools or the inspector is overridden on send

**Location:** `src/components/ToolControls.tsx:256–259`; `src/components/WorkspacePanel.tsx:121–129`; `src-tauri/src/chat.rs:1407–1412`.

**Trigger:** Open a conversation associated with project A, then choose folder B through Tools or the inspector and send a message using file/execution tools.

**Actual:** The picker saves B as the workspace, but leaves the conversation's project metadata pointing at A. `send_message` restores A before assembling tools. The visible folder choice and the assistant's effective working directory disagree. **Expected:** a folder selection either changes the task's effective workspace consistently or clearly remains an inspector-only selection.

**Evidence — source traced:** Both pickers update only the global workspace; the send path deliberately derives it again from task metadata. The Tools copy explicitly presents its picker as a way to enable workspace tools. No assistant write to a wrong folder was performed.

**Fix:** Establish one task-scoped workspace source of truth. Update project/task association when changing assistant scope, and represent independent inspector roots separately. Add a cross-layer test asserting the actual tool root after choosing B.

### A08 — P1: Trajectory can display one conversation's events under another and fork the wrong point

**Location:** `src/components/Trajectory.tsx:60–87`.

**Trigger:** Open A's trajectory, then switch to B before A's event request completes.

**Actual:** B's load returns early because `loading` is true. A's late response writes its events into the reused component. Clearing `loading` does not retrigger the effect. Fork buttons then use current conversation B with sequence numbers displayed from A. **Expected:** drop stale responses, clear A's rows, and load B independently.

**Evidence — executed, UI:** With a delayed event response, the only requested ID was `conversation-A`; after switching to B, the visible payload was still `conversation-A private content`. The mismatched fork arguments follow directly from `handleFork`. No real private conversation was involved.

**Fix:** Bind requests and rows to a conversation ID/request generation, cancel or ignore stale responses, and prevent actions on rows whose owner differs from the active conversation. Repro artifact: `trajectory.json`.

### A09 — P1: A settled background agent can make its parent conversation unsendable

**Location:** `src-tauri/src/subagents.rs:940–963`; `src-tauri/src/history.rs:65,74–86`; `src-tauri/src/chat.rs:991–997`; cache validity at `src-tauri/src/store.rs:1881–1888`.

**Trigger:** A background subagent completes or fails and appends its settlement notice to the parent conversation.

**Actual:** Both settlement writers append a `tool` message whose `request` omits `arguments`. Rebuilding model history requires every tool audit to have object-valued arguments and returns “A saved tool audit has invalid arguments.” The appended row also invalidates the cached history's latest-message condition, so the next send/preflight can fail before inference. **Expected:** a background completion remains readable and usable in the parent's future turns.

**Evidence — independently found by SWE-2 Max, source traced and reproduced against the current history parser:** An isolated Rust probe included the actual `history.rs` source, supplied the exact settlement JSON shape, and got the invalid-arguments error. Its message/attachment/alias support was stubbed; this was a parser-contract reproduction, not a full native background-agent session. The failed validation branch is independent of those stubs. Repro artifact: `background-history.log`.

**Fix:** Represent settlement as a distinct notification/event or write a complete valid audit through a shared constructor. Repair existing malformed settlement rows without discarding conversations. Add an integration test that settles a real synthetic background child and then prepares the next parent turn.

### A10 — P1: Unchecking file access and local execution leaves equivalent tools enabled

**Location:** `src-tauri/src/chat.rs:799–805,865–869,2326–2337`; `src-tauri/src/presets.rs:132–145`; `src/components/ToolControls.tsx:244,266–276`.

**Trigger:** Use Standard (or Creator), uncheck Workspace files and Local code, and retain a registered project. In Full access, no subsequent approval is required.

**Actual:** Source selection removes the dedicated workspace/execution backends, but the loop unconditionally appends preset harness aliases, including Standard's `file_read`, `file_write`, `file_search`, and `run_code`. The catalog dispatch still resolves the task workspace and interpreter and executes them. Tools can display “Tools · Off” while equivalent read/write/code tools remain offered. Auto-approve reads also still permits the read aliases. **Expected:** the file/code access controls govern all equivalent aliases, and the displayed tool state reflects the effective set.

**Evidence — source traced with executed native preset inventory:** The compiled Standard preset contains all four aliases; the live assembly loop has no `use_workspace`/`use_execution` filter for them. `harness::preset_offered` checks only the inherited offered list, not the source toggles. No unapproved file write or code execution was performed. The promised selection boundary is stated in `docs/PERMISSIONS.md` (“Full access changes approval behavior, not tool selection”).

**Fix:** Filter every alias by its required user-selected capability before publishing schemas, repeat that authorization at dispatch, and calculate UI counts from the effective backend tool inventory. Cover zero selected sources under Ask, Auto-approve reads, and Full access. Repro artifact: `preset-inventory.log`.

### A11 — P1: Models declared without tool support cannot make a plain chat request

**Location:** `src-tauri/src/chat.rs:865–869,1048–1057`; `src-tauri/src/inference.rs:158–161,300–305`; `src/lib/providers.ts:54–61`; `src-tauri/src/presets.rs`.

**Trigger:** Configure a verified provider model with context capacity and Tools = Unsupported, select it, deselect tool sources, and send ordinary text.

**Actual:** The UI considers the model ready, but every available preset adds at least one harness tool. `assemble_turn` sees nonempty tools while `backend.supports_tools()` is false and rejects the turn, advising the user to deselect tools. There is no effective empty-tool preset that satisfies that advice. **Expected:** a model explicitly configured for text-only/no-tools chat can receive a request with no tool schemas.

**Evidence — source traced with executed native preset inventory:** All seven current presets have nonempty harness lists, including Chat's three metadata tools. The backend maps `ToolSupport::Unsupported` to `supports_tools=false`, and the frontend readiness check does not exclude these models. A real provider request was not sent.

**Fix:** Support a real zero-tools mode for these models, omit implicit harness/system tools there, and make the readiness/error guidance agree with the effective capabilities. Add a synthetic-provider integration test proving plain chat succeeds without any `tools` payload.

### A12 — P2: Persisted prompts are restored as unsent drafts after inference errors

**Location:** `src/App.tsx:788–824`; `src/components/Chat.tsx:668–672`.

**Trigger:** The backend saves the user message, then inference fails.

**Actual:** App checks persistence but throws in both the saved and unsaved branches. Chat restores the original draft and attachments even when the prompt already exists in history. The ordinary Send action now duplicates it; a separate retry action is also visible. **Expected:** restore only unaccepted messages, while reporting inference failure separately for accepted messages.

**Evidence — executed, UI:** After one rejected inference request, history contained one user message and the composer again contained exactly `Important audit draft`. Repro artifact: `flows.json`, `persisted-failure.png`.

**Fix:** Make acceptance explicit in the send contract. Keep the documented retry-as-new-message behavior, but avoid silently repopulating an accepted prompt.

### A13 — P2: Ctrl+N uses a stale project selection

**Location:** `src/App.tsx:267–280,476–500`.

**Trigger:** Select a project through its “New chat in…” action, then press Ctrl+N without another busy/page/sidebar state change.

**Actual:** The keyboard effect retains an older `projectId` closure. It can report that a project must be added despite the selected folder already existing, or create the next draft under a previous project. The keyboard path also lacks the Sidebar button's first-project fallback. **Expected:** keyboard and visible New chat actions resolve the same current project.

**Evidence — executed, UI:** Project B remained selected, `/fixture/b` had been activated, and Ctrl+N displayed “Add a project folder first, then start a chat.” Repro artifact: `flows.json`, `shortcut.png`.

### A14 — P2: Project expansion and per-project actions are unavailable from the keyboard

**Location:** `src/components/Sidebar.tsx:518–550`; `src/workspace.css:791–802`.

**Trigger:** Navigate the project list without a mouse, particularly after a folder has been collapsed.

**Actual:** Expansion is attached to an unfocusable `div` with no keyboard handler or expanded state. Per-project New chat/Delete buttons are inside `display:none` until hover or focus-within; keyboard focus cannot enter an already hidden group. **Expected:** a focusable disclosure button with `aria-expanded`, and reachable actions that reveal on focus.

**Evidence — executed UI plus source trace:** Project B's header was a `DIV`, role `null`, `tabIndex=-1`; its action group computed to `display:none` with the mouse away. This is a WCAG 2.1.1 keyboard-access defect. Repro artifact: `accessibility-preflight.json`.

**Fix:** Use a semantic disclosure button and expose actions through a focusable control. Test keyboard expansion, starting a chat in a second project, and project removal without hover. Suggested interface follow-up: `$impeccable harden`.

### A15 — P2: Pause state leaks across conversations and offers Resume too early

**Location:** `src/App.tsx:182,267–310,504–515,1075–1084`; `src/components/Chat.tsx:984`.

**Trigger:** Pause a response and then create or select another conversation. Resume also appears immediately after pressing Pause while the current response is still running.

**Actual:** A single application-level `runPaused` boolean is set optimistically and is not reset/reloaded on conversation changes. A brand-new chat can show Resume; its handler returns immediately because there is no active conversation. **Expected:** paused state belongs to the actual run/conversation and Resume becomes available when a recoverable checkpoint exists.

**Evidence — executed, UI:** Resume was visible during the active request and remained visible in a new, empty Project B chat. Repro artifact: `pause.json`.

**Fix:** Derive control state from persisted/current run status, disable resume during an active send, and restore the prior state if pause fails.

### A16 — P2: Context preflight omits attachments and accepts stale responses

**Location:** `src/components/Chat.tsx:642–652,658,1012–1015`.

**Trigger:** Attach a large document without changing draft text; or issue a second preflight before the first response resolves.

**Actual:** Preflight receives only raw draft text, while send uses `composeMessage(draft, attachments)`. Attachments are absent from dependencies, and in-flight responses have no request/version guard. Overflow warnings can miss the effective payload or describe an older draft/conversation/model. **Expected:** estimate the actual send payload and render only results belonging to current input and selection.

**Evidence — executed UI for attachment omission; source traced for response ordering:** A 135,000-byte text attachment appeared, but the only preflight contained `Review the attachment` with no attached content. Backend send-time validation still limits context; this finding concerns misleading pre-send feedback, not a budget bypass.

**Fix:** Compose the same payload for preflight and send, include attachment/model revisions in its identity, and ignore late responses. Repro artifact: `accessibility-preflight.json`.

### A17 — P2: Offline mode does not guard all built-in retrieval aliases

**Location:** `src-tauri/src/harness.rs:265–306,389–395,558–563`; `src-tauri/src/web_search.rs:45–56`; compare guards at `harness.rs:320–335,573–580`.

**Trigger:** `offline_mode=true` is persisted and an otherwise enabled/approved `search`, `visit`, `web_fetch_url`, or `web_fetch` call runs.

**Actual:** These paths reach network retrieval without an offline check. `run_worker_with_settings` checks offline only for weather. `web_search` and `web_read` do check it. **Expected:** the documented external-retrieval policy applies consistently to built-in aliases.

**Evidence — source traced:** The offline helper tests establish the policy but do not exercise these dispatch paths. This is conditional on the persisted setting; no ordinary UI toggle for that setting was found. It is not a claim that shell or unknown MCP networking is isolated—those exceptions are documented.

**Fix:** Enforce retrieval policy centrally before network-capable dispatch, including worker health/fetch/search actions, while allowing offline access to already saved passages. Add dispatcher-level offline tests.

### A18 — P2: Artifact excerpts can exceed their declared context budget by orders of magnitude

**Location:** `src-tauri/src/artifacts.rs:71–82,257–293`.

**Trigger:** A tool returns a large preserved metadata field, such as a long `error` string.

**Actual:** `bound_tool_result` copies that field without a bound. Its final shrinking passes remove list items and trim selected excerpt/goal/instruction fields, but do not bound the preserved error. **Expected:** the final serialized result respects the advertised budget and points to the full artifact.

**Evidence — executed, native:** With a 100,000-character fake error and a **2,048-byte budget**, the helper returned **100,487 serialized bytes**, despite saving an artifact. This can turn a handled tool failure into a context overflow on the next model round.

**Fix:** Bound every preserved field and apply a final minimal-envelope fallback based on serialized byte length. Cover oversized metadata, Unicode, scalar results, and the smallest allowed budget. Repro artifact: `artifact-size.log`.

### A20 — P2: Trajectory silently stops at the first 1,000 events

### A22 — P2: A vulnerable development dependency remains locked

**Location:** `package-lock.json`, installed `source-map-js@1.2.1`; dependency paths Vite → PostCSS and jsdom → css-tree.

**Evidence — advisory:** `npm audit` reports GHSA-68fv-2mgg-jv7q as high severity. Versions before 1.2.2 accept malicious indexed-source-map offsets that can block the event loop. The [GitHub advisory](https://github.com/advisories/GHSA-68fv-2mgg-jv7q) identifies **1.2.2** as patched. `npm audit --omit=dev` is clean, and no shipped-app exploitation path was established; this is a developer/build-tool exposure, not an asserted high-severity production exploit.

**Fix:** Update the transitive dependency through a supported lockfile refresh and rerun build/tests/audit. Do not apply a blanket force upgrade.

### A23 — P2: Long tool runs never consume the round budget used for graceful finalization

**Location:** `src-tauri/src/chat.rs:1581–1591,2107,2426`; `src-tauri/src/continuation.rs:56–86`.

**Trigger:** A long non-web task continues using tools toward the 64-round cap without exhausting the separate search/fetch budgets.

**Actual:** The loop advances `round`, but `budgets.rounds_used` remains at its default zero. The continuation policy cannot reserve a final answer based on round exhaustion. The last ordinary tool round instead hits the hard “Tool round limit reached” error, leaving collected work without the intended final summary. **Expected:** reserve a tool-free final response before the cap, identifying incomplete work.

**Evidence — source traced, independently raised by SWE-2 Max and verified by Codex:** Every current reference to `rounds_used` is in the budget definition/default/checks or tests; the live chat loop never assigns or increments it. A 64-round model session was not executed.

**Fix:** Advance the budget once per actual model round and connect its finalization decision to the request's tool-free final-answer mode. Exercise the real loop with a synthetic provider that keeps requesting non-web tools near the cap.

### A24 — P2: Stop during preparation does not prevent the request from starting

**Location:** `src/App.tsx:576–616,1075`; `src-tauri/src/chat.rs:1414–1445`; `src-tauri/src/agent_run.rs:113–116`.

**Trigger:** Press Stop while conversation/tool setup or native turn assembly is still preparing the request.

**Actual:** The frontend continues its awaited setup and invokes `sendMessage` after the Stop request. In the backend, `assemble_turn` runs before `begin_run` clears pause and `state.cancel.send_replace(false)` clears cancellation; the watch subscriber is created afterward. A Stop/Pause that lands during this preparation window is discarded. **Expected:** cancelling preparation prevents a new model request or tool loop from starting.

**Evidence — independently raised by SWE-2 Max; executed UI plus source trace:** With a deliberately delayed conversation-creation fixture, Stop reached `cancelGeneration` at 784.7 ms, but `sendMessage` still started at 1,422.5 ms (`sends=1`). The native clearing/subscription order is visible in the cited source. This was not a live model timing test. Repro artifact: `preparing-cancel.json`.

**Fix:** Track cancellation through frontend preparation and avoid invoking the send after it has been cancelled. Establish a run-specific cancellation identity/subscription before asynchronous native assembly, and honor it before model/tokenizer requests. Checking a flag after clearing it would not solve the race.

## Patterns and defenses to retain

The recurring problem is **parallel implementations with different guarantees**. Capability-relative workspace reads coexist with an unconstrained search helper; pinned, bounded HTTP transport coexists with a legacy reqwest fetcher; per-task project scope coexists with a mutable global workspace. Tests exercise many strong helpers but miss paths that select weaker alternatives.

Async UI state also needs consistent ownership: requests should carry a conversation/input identity, and accepted messages, paused runs, project selection, and persisted settings should not be inferred from unrelated booleans or caught exceptions.

Existing defenses worth preserving:

- Native editor operations use capability-relative paths, reject linked entries, check hashes before replacement, preserve file permissions, and publish saves atomically. The native editor tests passed.
- Provider endpoints reject embedded credentials, require HTTPS remotely, disable redirects, use bounded response reads, and separate Claude authentication from Bearer authentication. Their wire/auth tests passed.
- The newer web transport pins DNS, checks redirects, enforces robots policy, and bounds concurrent work. Its 19 transport/render tests passed with the temporary loader.
- Main-window IPC is explicitly denied to inspector browser webviews (`src-tauri/src/lib.rs:357–367`).
- Unknown/model-written permission claims do not grant tool access. Auto-approval relies on backend classification; the A01 classification exposes why implementation parity matters.
- Runtime/model installers stream verified downloads, preserve partial transfer state, and check pinned hashes before publishing. This audit did not re-exercise full model downloads.
- Browser preview accurately disables native persistence/setup actions and explains the desktop boundary. Reduced-motion and theme behavior pass existing browser checks.

Intentional restrictions excluded from findings: account-subscription providers are explicitly nonselectable in this build; Daytona execution is intentionally disabled; local shell/MCP are documented as unsandboxed; Linux Wayland desktop input is explicitly rejected. None was treated as an accidental Windows backend failure.

## Recommended order

1. Close A01/A03/A10, repair the background-agent history contract in A09 and no-tools model path in A11, then remove the unbounded-read paths in A04. Consolidate the stronger implementations instead of maintaining two policy surfaces.
2. Fix project identity/scope (A02, A07), draft acceptance (A06, A12), and storage resilience (A05).
3. Fix conversation-bound async state and controls (A08, A13, A15, A16, A20, A24), then enforce offline policy, excerpt budgets, and round finalization (A17, A18, A23).
4. Use `$impeccable harden` for A14/A21 and `$impeccable clarify` for A19; finish interface work with `$impeccable polish`. These can be addressed individually or together, then checked with `$impeccable audit`.
5. Refresh the vulnerable development dependency, make the documented strict lint check pass, and repeat native release acceptance on Windows. Keep Linux platform failures separately tracked.
