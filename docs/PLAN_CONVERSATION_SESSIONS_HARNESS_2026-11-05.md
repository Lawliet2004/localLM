### 2.3 Reasoning effort: probable cause of long "thinking"

`reasoning_effort` is sent to remote OpenAI-format providers only for known OpenAI model families, and only when the provider has no declared controls (`inference.rs` L168–178, L460, L548). River's model list carries no capabilities, so GLM-5.3-Flash gets no effort field and runs at the server default, `max`, on every turn including trivial ones. The app's Quick/Think preference cannot take effect for it. **Inferred from code and the live response; confirm with a payload unit test in Phase 0.**

### 2.4 Parallel sessions: where blocking lives

I cannot reproduce "I can't open another session" without running the app. These are the concrete blockers found by reading. Phase 1 tests each one.

Frontend:

- `navigationBusy = modelBusy || savingTools || exporting || sessions.get('new').generating` (`App.tsx` L299). While a brand-new conversation is being created and started, tabs, back/forward, New and sidebar selection are disabled.
- `selectConversation` returns **silently** when `navigationBusy || toolSave.current` (L592). The click does nothing and gives no reason.
- `busy` includes `loading` (L297), and `send()` throws "Wait for the active operation" when `busy` (L649). Sending is blocked while any conversation is merely loading.
- The model picker is disabled when `generating || loading` (`Chat.tsx` ~L778). The Models page and sidebar receive `globalBusy` (any session generating), so no model or provider work is possible while any session runs, with no explanation.
- A hidden running session is shown from an in-memory copy of its messages (L627). That copy is owned by the `send()` closure, which makes reload, crash and restart recovery fragile.

Backend:

- `OperationGate` (`lib.rs` L143): a turn holds a shared lease and exclusive operations hold the exclusive lease. Exclusive callers (`commands.rs`): `save_provider`, `delete_provider`, `delete_provider_api_key`, `test_provider`, `test_provider_draft`, `list_provider_models`, `list_provider_models_draft`, `test_provider_inference`, `save_preferred_model`, `delete_conversation`, `load_model`, `unload_model`. All are refused while **any** turn runs, including read-only network probes and deleting an unrelated conversation. Starting a turn fails fast ("Another operation is in progress") while one of them runs.
- `store: Mutex<Store>` is one SQLite connection shared by every session. `assemble_turn` takes it about 20 times per turn; every journal event and message write goes through it. The audit confirmed no guard is held across `.await`. Whether this is a throughput problem has **not** been measured.
- No explicit cap on concurrent sub-agents or concurrent turns was found by searching for limit constants. Confirm in Phase 1.
- Local inference: slot 0 is pinned only while one run is active (`chat.rs` L1726), which is correct for cache reuse. Behaviour with several local sessions depends on llama.cpp `--parallel` slots.

### Phase 1 — Parallel sessions that actually work

1.1 **Reproduce first.** Native scenario: start a turn in A; within one second open or create B; start B; stop A; restart the app mid-run. Plus focused tests for each blocker in 2.4. Record which ones fail.
1.2 **Frontend:**
- Replace the single `busy` with `activeBusy` (this conversation's own state) and `exclusiveBusy` (model load/unload, provider edit). Remove `sessions.get('new').generating` from navigation; create the conversation id before streaming so the `'new'` key window disappears.
- `selectConversation` never fails silently: last click wins, superseded loads are discarded (the `selection` version already exists), and any real refusal shows its reason.
- Move per-conversation run state (messages, streams, approvals, errors, drafts) into an external store keyed by conversation id (`useSyncExternalStore`). Stream handlers write only to the store; the visible chat subscribes to one key. This replaces the `displayMessages` coupling and enables recovery.
- Show why model/provider pages are limited while sessions run, and which sessions are running, instead of a disabled button.

1.3 **Backend gate narrowing** (keep the existing API and messages where possible):
- Read-only network probes (`test_provider*`, `list_provider_models*`, `test_provider_inference`) stop taking the exclusive lease. Verify each has no state mutation first.
- `delete_conversation` takes the shared lease plus that conversation's turn lock.
- `save_preferred_model` affects only new conversations: shared lease.
- Provider edit/delete/credential change is refused only if a **running turn uses that provider**: record provider and model on the session-run registration (`session_runs.rs`). Verify the turn already holds its built backend so a later edit cannot change a running request.
- `load_model` / `unload_model` stay exclusive but conflict only with turns on the local runtime.
- Refusals return a structured reason naming the blocking sessions so the UI can offer "Stop it" or "Wait".

1.4 **Governor.** A `max concurrent turns` setting (default 4) with an honest queued state ("Waiting for a slot"), `Retry-After` handling for provider 429s (building on `inference_retry.rs`), and a local-runtime notice when `--parallel` slots are fewer than active sessions ("Local model serves N requests at a time; others wait").
1.5 **Restart recovery.** Add a `list_active_runs` command over the existing registry, rehydrate the session store on boot and webview reload, and mark orphaned runs interrupted with a **Continue** action (the pause/resume checkpoint exists).
1.6 **Store contention, measured not assumed.** Add timing instrumentation behind a flag; run four concurrent scripted streaming turns. Only if p95 lock wait is material (target: under 50 ms), introduce an ordered async journal writer per conversation. Preserve the audit's invariant that no store guard crosses an `.await`, and add a unique `(conversation_id, seq)` index through the `user_version` migration ledger.

Tests: Rust gate tests per narrowed command; concurrent `send_message_inner` with scripted SSE (needs sockets, so run on a permitted host and report "not run" here); `App.test.tsx` for overlapping starts, switch-during-creation and stale selection; native rig for the real scenario.

**Exit:** from the native rig, open B within 150 ms while A streams; both stream independently; Stop A leaves B running; restart marks both interrupted with Continue; a provider test or delete of an unrelated conversation works while A runs.

### Phase 2 — Typed live turn items (the data contract the UI needs)

The backend already knows when reasoning starts, when a tool call is decoded, dispatched, approved and finished. It just does not say so on the live channel. Adapt the item lifecycle used by Codex's app-server (thread, turn, item with started/updated/completed), referenced as a pattern in `HARNESS_WORKSPACE_2026-11-04.md`.

2.1 **Model.** `TurnItem { id, runId, round, kind, status, startedAt, endedAt?, parentItemId?, payload }`. Kinds: `reasoning`, `message` (commentary or final), `tool` (read, search, list, command, edit, web, mcp, other), `plan`, `approval`, `subagent`, `notice`, `error`, `compaction`. Statuses: running, completed, failed, interrupted, awaiting.
2.2 **Events.** `item.started`, `item.delta` (text append or output chunk), `item.updated` (arguments complete, status change), `item.completed`. Added as an optional `ChatEvent.item` field, so old clients ignore it. Persisted through the existing `session_events` table (new payload fields, no new table). Backend coalesces deltas to at most about 30 per second per item.
2.3 **Early tool visibility.** Emit `item.started` when the tool name is decoded, and `item.updated` as soon as `path` or `command` is parseable from the partial arguments, so "Editing `src/App.tsx`" appears while the model is still writing the call.
2.4 **One reducer.** A pure `reduceTurnItems(state, event)` used both live and to replay the journal. The golden corpus from 0.5 must satisfy **live result equals replay result** for every provider shape (GLM `reasoning_content` plus parallel tools; Claude `thinking` plus `tool_use`; Responses reasoning summary plus `function_call`; local `<think>` filter).
2.5 **Honest timing.** Durations come from backend-recorded delta timestamps, never inferred in the UI. If a provider returns no reasoning text, show no reasoning item.
2.6 **Legacy.** Keep `activityTools` and `activitySegments` only as the fallback for conversations recorded before this change, isolated in a `legacyActivity` module.
2.7 **Sub-agents** emit the same items with `parentItemId`, so the child transcript reuses the same reducer (Phase 4).

Tests: reducer unit tests from the corpus, live/replay parity, duplicate and out-of-order delivery, cancellation mid-item, provider fragment edge cases (already covered at the protocol layer in `CACHE_AND_TOOLS.md`; add item-level assertions).

**Exit:** a recorded GLM turn replays to the same item list as it produced live, and the timeline no longer needs polling for live updates (polling stays as recovery only).

6.6 **Metrics in the UI and export.** Extend `ResponseMetrics` with time to first output, model time, tool time, cache percentage and a JSON export that the benchmark script also reads.
