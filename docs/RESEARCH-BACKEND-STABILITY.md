The September 23 MiniCPM eval exports in `eval-results/minicpm` are regression inputs, not proof that every defect still exists in the current tree. The weather route and Docker tool gating have already changed; verify their behavior through the bundled worker and chat harness before marking them done.

## Corrections to the trace diagnosis

- Zero generated search queries proves a pipeline short circuit, not that the provider is offline. The result now reports `pipeline_no_queries`; `provider_unreachable` requires an observed transport failure.
- The current `QueryPlanner` clamps its budget to at least one query and falls back to the original question after a planner failure. The trace's zero queries came from the weather short circuit before planning; it was not evidence that the planner returned an empty list. A zero-query external-data result now triggers a separate provider health probe for diagnostic context.
- The quoted ~10 tokens/s was inferred from output characters and wall time. Model timings are now exported so runtime tuning can use measured decode speed and GPU offload rather than that estimate.
- A later local runtime log records 50 generated tokens in 2.127 seconds (23.03 tokens/s), illustrating why the trace's character-based ~10 tokens/s estimate should not be used as a tuning baseline. This later log entry is not attributable to either diagnosed trace.
- The app's first-load local context default is already capped at 8,192 tokens (`model_library::initial_config`). The trace's 131,072-token context came from a saved runtime configuration, so changing the default would not repair that trace. Preserve saved model profiles until a controlled benchmark shows a better setting.
- A warm Node worker is not yet justified: the bundled-worker regression took roughly half a second including two process launches. The 38-second URL call also included rendering and network work.
- The saved trace really contains two `tool_call` events without matching `tool_result` events in a run marked completed. The current chat path settles pending calls on pause/cancel/error. Startup repair now also appends an `outcome: unknown` result for an orphan inside a turn that already has `turn_end`, and changes a falsely completed run to `outcome_unknown`. Previously it repaired only unfinished tails. The repair is idempotent and does not replay the tool.
- A successful lexical claim match does not prove a source supports a claim. Citation URLs are now checked against successful tool outputs, while claim support still requires a stronger verifier or human review.
- The Hohmann trace's Python program itself used `2π√(a³/μ)` (a full orbital period) for a transfer that takes half an orbit. The correct result from the supplied constants is `π√(a³/μ) = 18,990.212 s = 5.275 h`. The velocity-only vis-viva check could not catch this. This is a model-generated calculation and test-design error; the execution backend ran the code it was given.
- The local eval driver now applies an independent Hohmann transfer-time oracle to the final answer and exits unsuccessfully if the result is wrong or cannot be parsed. The saved MiniCPM trace fails that check; a corrected 18,990 s or 5.28 h answer passes.
- Outgoing links on a fetched page are not retrieved sources. The citation allowlist and AREX evidence collector now follow only fetched documents and search-result collections; regression tests prevent linked but unread pages from being accepted.
- At the time of the original audit, Creator and Research offered one todo-list writer while Coding still offered legacy positional add/update tools. The integrated P11 fix removes those mutators from Coding's offered tool list while keeping their handlers available for historical calls.
- Worker installation uses a content versioned filename and atomic rename, so concurrent calls cannot start a partially written bundle. Health/open/fetch/search actions have shorter ceilings than full research; error messages discard Node warning and stack noise.
- Worker stdin, stdout, stderr, and process exit now share the action deadline and cancellation guard. Stdout and stderr enforce size limits as immediate failures. A regression test uses a producer blocked on a full pipe to confirm an oversized stream returns promptly instead of waiting for the child until the 240-second deadline. The worker now uses the backend's process-tree wrapper, so cancellation and timeouts also terminate a browser it launched for rendering.
- Worker deadlines use a timeout message recognized by the retry classifier; oversized stdout/stderr are treated as deterministic, nonretryable failures.
