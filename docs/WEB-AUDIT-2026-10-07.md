## Changes with measurable or reproducible benefit

- Title edit distance uses one rolling row instead of a complete matrix. A local microbenchmark of 150 nonidentical approximately 805-character title pairs measured a median **9,990.7 ms before and 317.0 ms after** over five measured runs following warm-up, about **31.5 times faster for that helper workload**. Its working array shrank from roughly 649,000 numeric cells to roughly 805. These are synthetic helper measurements, not an inference or whole-app speed claim; concurrent audit activity can affect timings.
- The existing five transport tests took **8.26 seconds before**. The same cases took approximately **4.1 seconds after**; four additional regressions made the final nine-test transport suite take approximately 6.2 seconds. A cold mock HTML visit fell from approximately 2,015 ms to 1,003 ms; a robots-denied cold request fell from approximately 1,011 ms to 1.3 ms. Same-host request starts still remain at least one second apart. Transient robots HTTP failures are rechecked after recovery instead of becoming permanent allow-all policies.
- Repeated agent/staged searches and direct page reads now use the existing caches rather than performing fresh requests every time. Tests verify a repeated identical query/page makes only one provider/transport call within its freshness window, while different freshness, provider-engine settings, stale documents, disabled caches, and partial query failures trigger fresh work.
- Document find computes its lowercase searchable text once. Open computes chunks once even when a requested section is absent. The worker no longer parses the same full research session twice for open/find.
- Research source/build code is **156 lines smaller than the entry snapshot**, before counting regression tests and this report. This includes removal of two unreferenced modules (`planning/query_schema.ts`, `verticals/vertical_provider.ts`) and unconsumed MMR, fact-result-type, and extraction-helper code. Security checks, failure isolation, citation validation, and document reading remain. The source budget can change if subsequent review repairs add code.

## Cache and full-document semantics

Search keys include provider identity/configuration, search-engine selections, result limits, planned queries/pages, and freshness. Cache entries use the shorter of the configured TTL and the freshness TTL. Successful batches with organic hits are cached; partial failed batches and empty pools are not retained as successful answers. Fallback results keep the provider that supplied them and remain subject to the same freshness limits. Existing legacy cache entries with older keys are simply missed and expire normally.

Document cache reads also check the stored retrieval time against the current request's freshness budget. A previously stored day-old page cannot satisfy a realtime request merely because its original storage TTL was longer. Redirects are cached under the requested URL while preserving the fetched final URL and metadata. Archived recoveries are not cached as live documents. Cache expiry never extends on a read.

Full fetched pages remain outside the model evidence package and are saved only as research documents; bounded excerpts/facts still enter synthesis. Open/find serves bounded passages from that saved text. The worker continues sanitizing external evidence on output, and network requests still use DNS-pinned transport, redirect validation, robots, byte/time limits, and render mediation. Caching does not turn a failed or snippet-only fetch into a live page.

The optional `src/web/extraction/minicpm-live-fixtures.test.ts` test subsequently **passed, running two fixture passes**, using the cached managed `llama-server` and `MiniCPM5-2B.Q6_K.gguf`. Initial total test time was **65.06 seconds**, including **44.56 seconds of Rust compilation**. After repairing its request recorder and narrowing its labels, the targeted fixture **passed again in 15.60 seconds** with cached Rust build output. The active recorder observed **26 JavaScript fetch calls**, including all model requests, with **zero external JavaScript requests**. The [latest fixture log](C:/Users/PAPANG~1/AppData/Local/Temp/locallm-live-recorder-2026-10-08-ihOXpd/real-model-suite.log) is temporary and may not persist.

The run exercised actual loopback model requests: ordinary completion; answering `19.99`/page 2 from text produced by the shipped extractor from a synthetic compressed PDF; comparing two supplied text sources; and forced `run_code` tool-call generation. The returned tool arguments passed through the shipped parser/catalog to real workspace execution, producing `21.59`, which the Rust harness saved and read back once. An HTTP stream was aborted after receiving a chunk, and a later request returned `PONG`. The server used a 2,048-token context; ordinary fixture completions were limited to 128 tokens.

The fixture now uses explicit labels for supplied evidence, generated tool calls, HTTP abort, and seeded Rust contracts. Its remaining limits are:

- **Generated calculation tool handoff:** It does not perform a web search. The model is told the exact expression and forced tool choice; the harness supplies the file writes. This validates model tool-call handoff and execution, rather than autonomous research/planning. The parsed-message flag is not an inference-request counter.
- **Seeded checkpoint recovery:** Rust seeds a completed-operation ledger and an unfinished write, calls recovery/checkpoint helpers, and verifies completed operations persist while the unfinished operation becomes unknown without replay. The model then receives the checkpoint in a direct prompt asking for `RESUMED`. No desktop chat process is paused/restarted/resumed. An unchanged file's content before/after also cannot independently detect an identical repeated write.
- **Generated weather tool/local completion:** The weather request generates a forced `web_search` call but never dispatches it. A fresh arithmetic prompt goes directly to loopback and does not load historical remote-provider state. The original fixture bypassed its recorder; all health, completion, and abort requests now pass through it, and assertions require observed health and at least 18 completion requests. The recorder covers this JavaScript process's fetch calls only; Rust/model subprocess traffic and other transports remain outside it. Zero external JavaScript requests therefore do not establish network isolation or production browser/provider gates.
- **Seeded constraints persistence:** The harness persists/reloads constraints extracted from known text. It does not invoke model-message compaction or demonstrate a long model-driven conversation retaining constraints after compaction.
- **HTTP abort/repeatability:** The stream test validates HTTP abort and a subsequent server response, rather than the desktop cancel action or cancellation of tools. It does not assert that the first chunk contains generated answer text. Two passes are compared in the log but equality is not required; several actual responses differ.

Separate Rust tests provide stronger code-contract evidence for the relevant helpers: `web_search::tests::offline_blocks_network_before_worker_install_but_allows_stored_actions` invokes the actual worker gate and permits stored open/find/verify actions; compaction tests invoke actual compaction against seeded messages and SQLite artifacts. These remain fixture-level evidence, separate from a complete desktop/model workflow.

## Limits and next priorities

1. **Native/live qualification:** The small direct MiniCPM fixture run above passed. Complete desktop inference/research, pause/restart/resume, and long-context workflows still need native qualification. Google, SearXNG, weather, currency, Wayback, and actual rendered retrieval depend on reachable services/configuration. Fixture passes, the managed-model run, and the public transport read do not establish their live availability.
2. **Honor mode budgets consistently:** The planner clamps searches to four while the deep default advertises six. Staged research derives page budgets internally rather than taking the legacy mode page limits, so normal/deep behavior deserves explicit contract tests before exposing further knobs. Avoid adding UI controls for settings that a path does not consume.
3. **Keep retrieval claims honest:** Lexical relevance, requirement matching, and conflict heuristics can miss paraphrases or overmatch shared words. They should remain bounded heuristics with explicit limitations. No embedding model, trained cross-encoder, comprehensive semantic verification, or OCR is present in the current production path.
4. **Measure the loaded app:** Local token generation, GPU/VRAM, context size, provider latency, and desktop stream rendering are separate bottlenecks. Future optimization should use representative long conversations/research tasks, time to first token, network request counts, and memory measurements rather than treating these helper speedups as universal application speedups.
5. **Retain useful simplicity:** Keep the agent research and no-model deterministic paths until their distinct behavior is covered by a shared contract. Remove unconsumed adapters/options instead of adding speculative providers or containers; add service/runtime dependencies only for demonstrated failures that simpler paths cannot handle.
